# 今日想看

飞牛影视媒体库随机选片器，用一个轻量网页决定今日想看。适合 NAS、本机电脑和小型 VPS，所有业务页面登录后使用。

保留功能：

- 飞牛连接、同步和设备直连封面
- 随机选片、筛选和影片库
- Webhook
- Telegram 机器人：`getmovie` 随机，`menu` 设置分类、年份与观看范围
- 每日、每周、每月自动推送
- 每日或每周自动同步新影片与已观看状态
- 运行记录

## Docker Compose

已登录后可在侧边栏「账号安全」修改密码。输入当前密码并两次确认新密码（至少 8 位、最多 256 字节）；保存后旧密码与此账户全部会话立即失效，需要重新登录。不改变首次部署的环境变量创建规则。

```yaml
services:
  movie:
    image: stylle/today-random-movie-web:latest
    container_name: today-random-movie
    restart: always
    environment:
      - USER=admin # 首次初始化用户名；之后修改环境变量不会覆盖账号
      - PASSWORD=change-this-password # 必改：至少 8 字符；仅首次创建
    ports:
      - "8080:8080" # 左侧访问端口可改，右侧不改
    volumes:
      - ./data:/data # 必须保留；左侧可改为宿主机专用目录
```

首次启动时，`USER` 和 `PASSWORD` 创建管理员。之后修改环境变量不会覆盖已有账号。

启动：

```bash
docker compose pull
docker compose up -d
```

访问 `http://NAS-IP:8080`，登录后在“管理设置”中保存飞牛连接并同步。定时同步可在“连接与同步”页启用；年份筛选支持起止范围。

无需 `.env`、setup-token 或域名变量。端口和数据挂载必须保留；不要把实际部署配置、密码或数据库上传 Git。

## Telegram 选片

管理设置 → Telegram 机器人：填写独立的 Bot Token，向自己的机器人发送 `/start`，再点击「检测连接 / 识别私聊 ID」。核对私聊 ID 后启用并保存；默认关闭，无需新增环境变量或公网回调。

- `getmovie` / `/getmovie`：按当前范围随机影片，结果只有「再随机一部」「打开飞牛影视」两个按钮，不展开设置项；没有可用播放链接时点击会提示配置飞牛。
- `menu` / `/menu`：唯一的范围设置入口，可设置媒体库（多选）、类型、地区、起止年份和排除已观看；支持分页。原生指令菜单仅保留 getmovie、menu，`/start` 只显示简短使用提示。
- 初始为全部分类、排除已观看。后台「默认随机范围」供网站、TG 默认模式和新建推送规则共用；TG 自定义范围单独保存，点击「恢复后台默认」重新跟随，已有推送规则不受影响。

只响应绑定的私聊，不开放给其他用户或群聊。请勿与随手传等应用共用同一个机器人 Token；一个机器人只能由一个实例接收消息。Token 加密保存在 data，网页不回传已存 Token，留空表示不修改。消息和播放链接交给 Telegram 保存，机器人聊天不是端到端加密；播放仍需设备能访问飞牛并登录。

## 规则通知

管理设置 → 自动推送 → 新建或编辑规则，在「通知渠道」选择 Webhook、Telegram 机器人，或两者同时发送。旧规则仍默认为 Webhook；选择机器人前，先保存并启用机器人设置，可用「发送测试通知」确认送达，无需重复填写 Token。

每日、每周、每月和「立即运行」均使用规则自身的选片范围，不受 TG 菜单自定义范围影响。双渠道只选一次，发送同一部影片；一个失败仍尝试另一个，结果在「运行记录 → 通知记录」分渠道显示。自动规则每周期最多尝试一次，不承诺送达或自动补发；部分失败后请先核对成功渠道，手动再次运行会重新选片、再次发送所选全部渠道。

机器人规则通知也只显示上述两个按钮；点击「再随机一部」沿用该条通知发送时的规则范围，仅在当前私聊返回新结果，不额外重发 Webhook。结果按钮有效 30 分钟；更新前已发送的旧消息不会自动改版，请发送新指令查看。

## 重置管理员

```bash
docker exec -e USER=newadmin -e PASSWORD=new-password today-random-movie /app/today-random-movie admin-sync
```

执行后旧会话全部退出，新账号立即生效。

## 数据

`/data` 包含：

- `app.db`：账号、配置、影片索引、推送规则和记录
- `secret.key`：飞牛账号密码加密密钥
- `posters/`：已有封面缓存，仅用于回退；不会自动下载或补充

备份整个 `/data` 即可。飞牛账号密码使用 AES-256-GCM 加密保存。

### 封面来源与 TMDB 配置

飞牛负责同步影片列表、年份和已观看等信息；本服务不会下载飞牛图片。浏览器按已保存优先级加载启用的数据源（豆瓣、TMDB、豆影、已有缓存与占位图）；图片失败或可见图片等待超过 8 秒后继续回退。`/data/posters` 仅只读回退，升级保留旧缓存，不自动从飞牛补充。

在「管理设置 → 影视数据源」填写自己的 TMDB API Key 或 API Read Access Token，点击保存；随后可以检测已保存的来源。密钥由服务端加密保存，读取接口只返回是否已配置，留空保持原密钥，可显式清除。密钥不会写入网页、图片 URL、日志或示例。无需增加 Compose 环境变量。

已有外部图片地址可以直接使用；缺少地址时，服务端会按已知豆瓣/TMDB ID，或片名与年份查询元数据，浏览器再直接下载匹配图片。无需重新同步影片列表。元数据成功查询缓存 24 小时，无结果/来源失败缓存 10 分钟；同一影片的并发查询合并，最多同时查询四部影片。保存设置或点击「重新查询封面」可使旧查询缓存失效。服务端网络用于查询小型元数据，访问设备网络用于下载图片。

豆瓣使用网站公开信息入口，不需要豆瓣密钥，但不承诺为稳定开放 API；访问限制、验证码或无法匹配时继续尝试 TMDB。没有配置有效 TMDB 密钥且豆瓣不可用时，将使用旧缓存或占位图，不会静默改为请求飞牛。匹配片名时校验年份，避免同名影片误配；访问设备也需要能访问 `*.doubanio.com` 和 `image.tmdb.org`。

TMDB 配置说明：[应用认证](https://developer.themoviedb.org/docs/authentication-application)、[申请密钥](https://www.themoviedb.org/settings/api)。本产品使用 TMDB API，但未经 TMDB 背书或认证。

## 网页整站备份与异地恢复

在「管理设置 → 备份与恢复」下载完整 ZIP 备份包，包含账号、飞牛连接、影片索引、筛选偏好、推送规则、Telegram 配置、日志、已有封面缓存及 secret.key。导出使用 SQLite 一致性快照，排除浏览器登录会话。包内包含解密配置所需的密钥，ZIP 本身不加密，请存放在受保护的位置。

在另一台机器部署同一项目的相同或兼容新版本，先用新部署账号登录；选择备份包，核对文件名，勾选替换确认后导入。系统先检查包类型、路径、文件校验和、数据库及密钥，再保留原数据至 `/data/previous-*`，自动重新加载服务。随后使用备份中的原账号/验证器登录；不需要手动重启或复制密钥。无效备份不会替换当前数据。单包解压内容上限 20 GB，需为上传包、展开包及原数据预留空间。

迁移的是应用数据，不含 Docker 端口、挂载目录、反向代理、TLS 证书及应用外部文件。新环境仍需能访问保存的外部服务地址，并具备对应网络权限；环境变量 USER/PASSWORD 不会覆盖恢复的账号。不要把原实例和恢复实例同时连接同一个 Telegram 机器人。恢复前请另行导出当前数据；确认恢复正常后再自行清理回退目录。

影视视频本体仍位于飞牛媒体库，不在本应用备份内。


## 可排序数据源与 Telegram 封面

在「管理设置 → 影视数据源」独立配置豆瓣公开信息、TMDB、豆影 DoubanInfo、已有缓存与占位图。用上下箭头排序，取消勾选表示优先级 0；占位图始终最后启用。保存会使旧查询缓存失效，现有 TMDB 密钥留空保留，豆影密钥单独加密，整站备份包含两者。

豆瓣直接查询公开网站信息，不使用已经停止开放申请的旧版 v2 Key；访问可能受 IP/入口限制。应用保守限制公开查询频率，识别中文片名附原文名，仍校验年份，受限时继续后续来源。不会绕过验证码。

[豆影官方文档](https://doubaninfo.com/api/api_usage.php)：需申请自己的 API Key，使用 X-API-KEY 请求头。免费额度 10 次/分钟、200 次/天；应用至少间隔 6.1 秒，并保守采用滚动 24 小时 200 次上限，计数随数据库持久化。429 后冷却，限流时跳过并使用后续来源。第三方实际额度/访问权限仍以账号为准；不同实例共用 Key 时会共享服务商额度。豆影图片仅接受其官方 HTTPS dbposter 地址，不把 Key 发送给浏览器。

自动推送、getmovie、再随机都支持封面照片及原操作按钮；Telegram 自行获取公共图片，或上传已有本地缓存，不下载飞牛封面。图片失败后退为原文字。Telegram 发图路径使用模拟接口验证，不自动向真实聊天投递测试内容。

元数据只为缺失的简介补充内容，不覆盖已有飞牛简介、账户范围或推送筛选。新数据源需要相应密钥；未填写豆影 Key 时会跳过该源。

## 维护与验证

格式、共享组件、反向代理与平台验收见 [维护约定](docs/MAINTENANCE.md)。升级前备份完整数据目录及应用密钥，保留原数据卷。

密钥文件损坏或已有数据库缺失 secret.key 时服务会停止启动，避免覆盖原加密信息；请恢复匹配的完整备份。退出遇到网络错误会保留当前界面并提示重试，成功退出会撤销该账户所有网页会话。登录有账户与客户端组合限速，浏览器写请求需来自本站。

连接／通知测试支持当前表单草稿，无需先保存；测试不保存、不启用配置。详见 [连接与通知测试](docs/integration-tests.md)。

## 通知绑定与连接测试

Telegram 采用「Token → 保存 → 生成绑定码 → 私聊 `/bind`」统一流程，自动注册机器人菜单，无需手填 Chat ID 或发送测试消息。Webhook／飞牛支持直接测试当前表单而不保存。固件仅保留 Webhook／MQTT。详见 [配置说明](docs/integration-tests.md)。
