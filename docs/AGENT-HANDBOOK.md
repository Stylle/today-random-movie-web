# 开发与维护约定

## 界面

使用统一的亮色、暗色、跟随系统主题和中英界面文案。主题只影响显示，不读取业务内容、不发送业务请求，不清空草稿或登录状态。消息正文、影片元数据、文件名和发布说明不自动翻译。

独立控件采用 8px 圆角，内容面板采用 10px 圆角，复选框采用 4px 圆角。鼠标点击不保留额外焦点外圈；键盘导航保留有边界的 focus-visible 指示。不要为消除视觉问题而删除键盘可见焦点。

菜单保留关于入口；已登录页面不重复显示主题设置或关于按钮。登录页只显示用户需要的登录说明；部署环境变量、数据文件路径、维护命令写在部署文档中。

## 认证、隐私与持久化

保留各项目原有认证方式、权限、CSRF、上传边界和隐私规则。凭据在服务端加密保存，读取接口只返回是否已配置；输入留空保留已有密钥。不要在日志、网页、示例、截图或说明中输出真实凭据。

数据目录固定为 /data，升级和回滚必须保留完整目录及配套应用密钥。禁止通过删除数据卷或重建数据库解决迁移问题。备份可能包含账号、附件与应用密钥，需要独立保护。

Telegram 默认关闭，每个服务使用独立机器人。Webhook 与远程存储保留协议校验、超时和目的地址限制；测试与正式投递分别记录。不因界面统一而更改其他应用的通知行为。

## 公开项目与发布

README 优先提供最简 Docker Compose：公开镜像、访问端口、持久化目录，以及必要的首次账号配置。可选集成写入专门文档，不要求用户准备无用的环境变量或 .env。

源码与 Docker 镜像不包含真实部署地址、个人邮箱、开发机器路径、凭据、数据库、用户文件或备份。文档使用 example.com、演示账号和占位地址。保留原作者与第三方合法署名、许可证及依赖声明。

发布前检查依赖锁文件、前端构建、业务回归和容器健康；保留升级前的数据备份。真实部署后验证登录、上传、数据持久化和非 root 主进程。未推送的镜像不得描述为已发布。

Docker Hub 发布凭据使用 DOCKERHUB_USERNAME、DOCKERHUB_TOKEN；GitHub Actions 使用权限最小的 GITHUB_TOKEN。本机通过官方登录或系统凭据管理器授权。开发交接文档只登记凭据名称与用途，不登记真实值。

## 当前业务约定

- 「账号安全」自助修改当前账户密码，校验旧密码、新密码确认；服务端事务更新密码并撤销该账户全部会话。登录与改密共用串行锁，避免旧密码的并发登录越过撤销；保持原有密码登录方式。

- 今日想看、影片库、管理栏目及关于共用侧栏；手机使用抽屉导航。主题、语言切换位于顶栏，退出登录位于侧栏底部账号区，按钮文字水平和垂直居中。
- ratingMin/ratingMax 筛选范围为 0–10；旧配置未指定范围时不限评分。无评分、0 或无效评分按 10 分参与匹配，不改写原元数据。
- 网站选片、影片库、后台默认偏好和推送规则共用评分匹配逻辑。
- 影片库按当前列数显示每页四整行，仅最后一页允许不足；筛选条件变化重置页码，过期请求不能覆盖新结果。

- 封面小型元数据由服务端查询，图片只由浏览器下载；禁止恢复飞牛封面代理。优先豆瓣、TMDB，再只读旧缓存与占位图。TMDB 密钥使用 poster_tmdb_key 加密字段；后台仅返回配置状态。查询受并发、TTL、同名年份校验约束。
- 平板（1280px 及以下）筛选区在影片卡片上方，封面保持 2:3；长简介折叠。

- 数据来源菜单允许豆瓣、TMDB、豆影、旧缓存排序与停用（0），占位图始终最后。豆影 Key 独立加密；额度持久化，至少间隔 6.1 秒，滚动 24 小时不超过 200 次，不能通过刷新查询或重启清零。
- 中文菜单统一四字。Telegram 支持外部图片及旧缓存照片，失败退原文字和按钮；不下载飞牛封面，不自动向真实聊天发送测试消息。

## 通知与测试约定

配置权限、账户模型保持原样，不新增分用户配置。Telegram 使用保存 Token、一次性绑定码、私聊 /bind；不恢复手填 Chat ID 和测试发送按钮。绑定和启动后注册原有业务菜单。Webhook/飞牛直接测试当前草稿，不保存、不启用、空密钥只在服务端合并；保存与测试互斥并拒绝过期结果。共享模块及 Vue 面板按 shared-components.json 同步。详见 integration-tests.md。
