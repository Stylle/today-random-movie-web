# UI 升级与兼容说明

版本：0.5.3 → 0.6.0。

## 已改内容

统一浅灰/暗黑/墨绿主题、直角组件、字号/间距/44px热区、手机抽屉、表单与记录展示；新增关于弹窗、独立 /about.html、原始版权与 MIT 许可入口。没有安装新 UI 框架、Node 服务、Pinia 或外部字体，不增加服务端常驻任务。

保留默认选片范围、上一部、播放、影片搜索/分页、年份区间、定时同步、Webhook、Telegram 与推送规则。手机影片库改为单列，完整简介不截断。镜像新入口负责专用 data 权限准备，然后以10001:10001运行。

## 升级步骤

1. 使用应用支持的备份，或先停机再复制完整 data，包括数据库、密钥、附件与索引；保留旧镜像digest。
2. 拉取实际已发布的新镜像，或在此源码版本构建。未完成发布的标签不能假设可拉取。
3. 保持相同服务与 data 挂载，仅重建容器。不要执行 docker compose down -v。
4. 验证登录、配置、消息/版本/影片、附件、通知，再确认是否清理旧镜像。

业务API、数据库schema、账户、密钥和文件布局不变，无需导入导出或清库。主题仅改变颜色，不改变认证；随手传不改为账号密码登录，固件签名项目不降级。

## 不能自动兼容的目录情况

入口仅处理专用数据目录中的普通文件/目录，拒绝符号链接、硬链接、特殊文件、嵌套挂载。NAS的只读ACL或共享根目录不适合直接当 data。

如果遇到这些情况：停机→备份→复制到新的独立普通目录或命名卷→保留原目录不删→更新Compose挂载→启动验证。不要对NAS整个共享目录递归chown，不要chmod 777。若显式指定user，必须保证该用户对data有读写权限；PUID/PGID不是本项目支持的参数。cap_drop:[ALL]与root权限初始化不兼容，需预先准备卷并指定非root user。

## 回退

本次没有schema变更，通常可以停机并换回旧镜像；保留同一 data。若旧版以其他UID运行而无法写入，针对专用目录恢复正确所有权，或使用升级前备份恢复到另一独立卷核验。不要一边运行一边复制SQLite文件来做一致性备份。

## 功能与安全边界

主题/关于脚本不调用业务API、不读取登录Token、不加载外站脚本。关于源码链接不会附带任何凭据。各项目原有CSRF、会话、上传、路径、Markdown/链接净化、SSRF与权限策略保留。

不同项目的登录和通知业务并不相同；统一UI不等于抹平权限。通用能力对照、Webhook/TG复用标准、README模板与发布凭据安全配置见 [Agent手册](AGENT-HANDBOOK.md)。
