# 部署与使用

## 快速部署

优先使用 [README 的最简 Compose](../README.md#docker-compose) 或 [镜像模板](../docker-compose.hub.yml)。NAS 管理页面可直接粘贴 YAML；命令行保存为 `compose.yaml` 后执行 `docker compose up -d`。不需要源码构建、`.env` 或额外数据库。

| 项目 | 是否需要修改 | 说明 |
| --- | --- | --- |
| `PASSWORD` | 必改 | 至少 8 字符，仅首次创建管理员 |
| `USER` | 可保留 admin | 首次用户名需 3–32 位字母、数字或 `_.-` |
| `ports` 左侧 | 按需 | 访问端口，右侧容器端口 8080 保留 |
| `volumes` 左侧 | 必须保证持久化 | `./data` 或专用绝对目录，容器内仍为 `/data` |
| 域名、setup-token、受信代理 | 不需要 | 当前版本不使用旧部署参数 |

镜像支持 amd64 / arm64。相对目录以 Compose 项目所在位置为准；NAS 界面不能明确项目路径时使用专用绝对目录。容器能看到目录不等于有写权限，宿主机 ACL、只读挂载和远程文件系统限制都可能导致启动失败，不要对无关目录执行递归改权。

## 首次使用

1. 打开 `http://服务器IP:8080`，使用配置的管理员账号登录。
2. 在“连接与同步”保存飞牛影视地址与账号，先测试连接，再同步影片。
3. 在影片库浏览或筛选，在“今日想看”随机选片。
4. 需要自动化时再配置 Webhook、推送规则与定时同步。

容器中的 `localhost` 指向容器自身，不是 NAS；飞牛和 Webhook 地址应为容器实际可达的地址。浏览器访问入口与飞牛服务地址是两个独立配置，不能互相替代。

## 同步与推送

同步更新新影片信息及已观看状态，可手动触发，或在“连接与同步”设置每日 / 每周执行。自动推送支持每日 / 每周 / 每月，在页面设置发送时间、筛选条件和 Webhook。首次先使用测试发送，再核对“运行记录”中的结果。

宿主机关机、休眠或网络故障会影响定时任务。不要仅凭浏览器能打开 Webhook 就判断容器能访问；请核对接收端与运行记录，避免把连接测试成功等同于全部定时规则已正确启用。

## Telegram 机器人与默认随机范围

此功能默认关闭。用官方 [@BotFather](https://t.me/BotFather) 的 `/newbot` 创建本项目专用机器人，在管理设置的「Telegram 机器人」填写 Token；先私聊机器人发送 `/start`，再检测并核对 Chat ID，启用保存。检测期间不会自动绑定未知用户。多个私聊 ID 时请核对选择，已启用时仅返回当前绑定 ID，改绑前先关闭机器人。

不需要域名、公网回调或新增 Compose 参数，只需容器能通过 HTTPS 访问 `api.telegram.org`；必要时可自行配置标准 `HTTPS_PROXY`。不要与随手传或其他程序共用同一 Token，也不要同时运行两个使用相同 Token 的实例；已有 Webhook 会被提示冲突，不会擅自删除。

| 指令 | 作用 |
| --- | --- |
| `getmovie` 或 `/getmovie` | 随机影片，结果仅含「再随机一部」「打开飞牛影视」两个按钮 |
| `menu` 或 `/menu` | 唯一的范围设置入口，也支持 TG 原生指令菜单 |
| `/start` | 首次启用的简短指令说明，不展开设置菜单 |

菜单支持媒体库多选、影片类型、地区、起始/结束年份、是否排除已观看。候选较多时分页显示，所有分类不选即全部。年份起止反向时自动调整顺序。按钮有效 30 分钟，过期后重新发送菜单指令；旧配置的按钮不会继续改变新配置。无匹配影片时会提示调整范围或先同步媒体库。

影片结果、规则通知不再附带设置项。规则通知中的「再随机一部」沿用发送时的规则范围，仅回复当前私聊，不额外触发 Webhook；普通 getmovie 的再随机跟随当前 TG 范围。缺少飞牛地址时，「打开飞牛影视」会提示后台配置，不生成假链接。旧消息不会自动修改，新指令和新通知使用精简样式。

后台「默认随机范围」初始为全部分类、排除已观看；网站首次进入、TG 未自定义时和新建推送规则使用同一默认值。TG 自定义只影响对应私聊，保存在 data，不覆盖后台或网站当前已打开的筛选；点击「恢复后台默认」立即重新跟随。已有自动推送规则保留各自条件。已观看状态来自最近一次飞牛同步，需要时启用定时同步。

只有指定私聊及本人发出的命令能选片或修改范围；不响应其他用户、机器人、群聊或频道。该功能不会触发额外 Webhook。TG 推荐也会记入「运行记录」，与网站共用近期去重逻辑。

接收进度和已选响应先落盘，重启/网络重试不会给同一条命令重新随机另一部；跨系统不能保证恰好一次送达，Telegram 已收件但响应丢失时可能重复收到同一结果。关闭或修改绑定会取消请求，旧的未完成回复不会发送给新的绑定。后台可查看最近处理时间与错误。

Token 使用 `secret.key` 加密存入数据库，读取配置不会返回 Token；输入框留空保存表示保留。备份与恢复必须同时保留数据库和密钥，并停止旧机器人实例。机器人聊天不是端到端加密，影片详情与飞牛链接会由 Telegram 保存；链接不包含站点或飞牛登录凭据，但播放需要设备能访问目标地址并完成飞牛登录。不要把 Token、真实链接、数据目录或带配置截图提交到 Git。

## 规则通知渠道

在「自动推送」中新建或编辑规则，选择 Webhook、Telegram 机器人或双渠道。旧数据自动升级，原规则保持 Webhook；只用机器人时不需要填写 Webhook URL。先在机器人设置中保存并启用 Token、绑定私聊，点击「发送测试通知」检查实际投递。

自动触发和「立即运行」使用同一规则的筛选、时间与通知渠道。规则范围与机器人菜单自定义范围独立。双渠道仅随机一次并发送同一影片，一个失败不阻止另一个；「运行记录 → 通知记录」分别展示渠道、结果、规则 ID 和错误，未配置渠道或无符合条件影片也会记录失败。

自动推送每周期最多尝试一次，不自动重试，以免网络结果不确定时重复通知；手动再次运行会重新选片并重新尝试全部选中渠道。变更或关闭机器人设置会取消旧设置的在途通知，但已送达的信息无法撤回。清空/删除站点历史也不会删除 Telegram 中的消息。

## 账号重置

已有数据库不会被新的 USER / PASSWORD 自动覆盖。使用以下命令重置，替换账号和密码：

```bash
docker exec -e USER=newadmin -e PASSWORD='replace-with-a-new-password' today-random-movie /app/today-random-movie admin-sync
```

旧会话会失效。实际部署密码不要提交到仓库，也不要随完整命令截图公开。

## 备份、更新与恢复

`/data/app.db` 保存账号、配置、影片索引和记录，`secret.key` 用于解密飞牛凭据，`posters/` 为已有封面缓存，仅用于回退。**密钥与数据库必须一起备份**；只复制数据库无法恢复加密凭据。

停容器后备份整个挂载目录，再执行 `docker compose pull` 和 `docker compose up -d`。恢复时先停容器，保存当前数据的另一份备份，再还原完整目录；不要向正在运行的 SQLite 覆盖文件。不要执行 `docker compose down -v` 删除命名卷。

## 故障排查

| 现象 | 优先检查 |
| --- | --- |
| 启动反复退出 | `docker compose logs --tail=100`、初始密码长度、数据目录写权限 |
| 网页打不开 | 容器状态、宿主机 IP、左侧端口、防火墙及端口占用 |
| 改环境变量账号不变 | 已有库按设计保留账号，使用 admin-sync |
| 同步失败 | 容器到飞牛的连接、账号权限、服务地址和运行记录 |
| 外部封面失败 | 访问设备到豆瓣/TMDB 的网络；两者失败后读取已有缓存，没有缓存显示占位图 |
| 推送未收到 | 规则通知渠道、启用状态与时区；Webhook 测试或机器人「发送测试通知」；通知记录中的分渠道结果 |

本项目不负责宿主机防火墙或穿透服务的安全。公网暴露入口时由部署者配置 HTTPS、强密码与访问范围；飞牛凭据加密不等于附件或整个数据目录被加密。


### 封面来源与 TMDB 配置

飞牛负责同步影片列表、年份和已观看等信息；本服务不会下载飞牛图片。浏览器按「豆瓣图片 → TMDB 图片 → 本地已有缓存 → 占位图」加载；图片失败或可见图片等待超过 8 秒后继续回退。`/data/posters` 仅只读回退，升级保留旧缓存，不自动从飞牛补充。

在「管理设置 → 连接与同步 → 封面来源」填写自己的 TMDB API Key 或 API Read Access Token，点击保存；随后可以检测已保存的来源。密钥由服务端加密保存，读取接口只返回是否已配置，留空保持原密钥，可显式清除。密钥不会写入网页、图片 URL、日志或示例。无需增加 Compose 环境变量。

已有外部图片地址可以直接使用；缺少地址时，服务端会按已知豆瓣/TMDB ID，或片名与年份查询元数据，浏览器再直接下载匹配图片。无需重新同步影片列表。元数据成功查询缓存 24 小时，无结果/来源失败缓存 10 分钟；同一影片的并发查询合并，最多同时查询四部影片。保存设置或点击「重新查询封面」可使旧查询缓存失效。服务端网络用于查询小型元数据，访问设备网络用于下载图片。

豆瓣使用网站公开信息入口，不需要豆瓣密钥，但不承诺为稳定开放 API；访问限制、验证码或无法匹配时继续尝试 TMDB。没有配置有效 TMDB 密钥且豆瓣不可用时，将使用旧缓存或占位图，不会静默改为请求飞牛。匹配片名时校验年份，避免同名影片误配；访问设备也需要能访问 `*.doubanio.com` 和 `image.tmdb.org`。

TMDB 配置说明：[应用认证](https://developer.themoviedb.org/docs/authentication-application)、[申请密钥](https://www.themoviedb.org/settings/api)。本产品使用 TMDB API，但未经 TMDB 背书或认证。

## 网页整站备份与异地恢复

在「管理设置 → 备份与恢复」下载完整 ZIP 备份包，包含账号、飞牛连接、影片索引、筛选偏好、推送规则、Telegram 配置、日志、已有封面缓存及 secret.key。导出使用 SQLite 一致性快照，排除浏览器登录会话。包内包含解密配置所需的密钥，ZIP 本身不加密，请存放在受保护的位置。

在另一台机器部署同一项目的相同或兼容新版本，先用新部署账号登录；选择备份包，核对文件名，勾选替换确认后导入。系统先检查包类型、路径、文件校验和、数据库及密钥，再保留原数据至 `/data/previous-*`，自动重新加载服务。随后使用备份中的原账号/验证器登录；不需要手动重启或复制密钥。无效备份不会替换当前数据。单包解压内容上限 20 GB，需为上传包、展开包及原数据预留空间。

迁移的是应用数据，不含 Docker 端口、挂载目录、反向代理、TLS 证书及应用外部文件。新环境仍需能访问保存的外部服务地址，并具备对应网络权限；环境变量 USER/PASSWORD 不会覆盖恢复的账号。不要把原实例和恢复实例同时连接同一个 Telegram 机器人。恢复前请另行导出当前数据；确认恢复正常后再自行清理回退目录。

影视视频本体仍位于飞牛媒体库，不在本应用备份内。
