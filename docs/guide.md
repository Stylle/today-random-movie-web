# 部署与使用

## 快速部署

优先使用 [README 的最简 Compose](../README.md#docker-compose) 或 [镜像模板](../docker-compose.hub.yml)。NAS 管理页面可直接粘贴 YAML；命令行保存为 `compose.yaml` 后执行 `docker compose up -d`。不需要源码构建、`.env` 或额外数据库。

| 项目 | 是否需要修改 | 说明 |
| --- | --- | --- |
| `PASSWORD` | 必改 | 至少 8 字符，仅首次创建管理员 |
| `USER` | 可保留 admin | 首次用户名需 3–32 位字母、数字或 `_.-` |
| `ports` 左侧 | 按需 | 访问端口，右侧容器端口 8080 保留 |
| `volumes` 左侧 | 必须保证持久化 | `./data` 或专用绝对目录，容器内仍为 `/data` |
| 域名、setup-token、受信代理 | 不需要 | 当前版本不使用旧部署参数 |

镜像支持 amd64 / arm64。相对目录以 Compose 项目所在位置为准；NAS 界面不能明确项目路径时使用专用绝对目录。容器能看到目录不等于有写权限，宿主机 ACL、只读挂载和远程文件系统限制都可能导致启动失败，不要对无关目录执行递归改权。

## 首次使用

1. 打开 `http://服务器IP:8080`，使用配置的管理员账号登录。
2. 在“连接与同步”保存飞牛影视地址与账号，先测试连接，再同步影片。
3. 在影片库浏览或筛选，在“今日想看”随机选片。
4. 需要自动化时再配置 Webhook、推送规则与定时同步。

容器中的 `localhost` 指向容器自身，不是 NAS；飞牛和 Webhook 地址应为容器实际可达的地址。浏览器访问入口与飞牛服务地址是两个独立配置，不能互相替代。

## 同步与推送

同步更新新影片信息及已观看状态，可手动触发，或在“连接与同步”设置每日 / 每周执行。自动推送支持每日 / 每周 / 每月，在页面设置发送时间、筛选条件和 Webhook。首次先使用测试发送，再核对“运行记录”中的结果。

宿主机关机、休眠或网络故障会影响定时任务。不要仅凭浏览器能打开 Webhook 就判断容器能访问；请核对接收端与运行记录，避免把连接测试成功等同于全部定时规则已正确启用。

## 账号重置

已有数据库不会被新的 USER / PASSWORD 自动覆盖。使用以下命令重置，替换账号和密码：

```bash
docker exec -e USER=newadmin -e PASSWORD='replace-with-a-new-password' today-random-movie /app/today-random-movie admin-sync
```

旧会话会失效。实际部署密码不要提交到仓库，也不要随完整命令截图公开。

## 备份、更新与恢复

`/data/app.db` 保存账号、配置、影片索引和记录，`secret.key` 用于解密飞牛凭据，`posters/` 为缓存。**密钥与数据库必须一起备份**；只复制数据库无法恢复加密凭据。

停容器后备份整个挂载目录，再执行 `docker compose pull` 和 `docker compose up -d`。恢复时先停容器，保存当前数据的另一份备份，再还原完整目录；不要向正在运行的 SQLite 覆盖文件。不要执行 `docker compose down -v` 删除命名卷。

## 故障排查

| 现象 | 优先检查 |
| --- | --- |
| 启动反复退出 | `docker compose logs --tail=100`、初始密码长度、数据目录写权限 |
| 网页打不开 | 容器状态、宿主机 IP、左侧端口、防火墙及端口占用 |
| 改环境变量账号不变 | 已有库按设计保留账号，使用 admin-sync |
| 同步或封面失败 | 容器到飞牛的连接、账号权限、服务地址和运行记录 |
| 推送未收到 | Webhook 测试结果、规则启用状态、时区、接收端记录 |

本项目不负责宿主机防火墙或穿透服务的安全。公网暴露入口时由部署者配置 HTTPS、强密码与访问范围；飞牛凭据加密不等于附件或整个数据目录被加密。
